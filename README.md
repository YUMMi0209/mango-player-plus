为芒果TV设计的视频辅助插件：快捷键打点、变速预览、截图录制，日志面板一键导出片段表。

## 0. 安装教程

Chrome 与 Edge 均为 Chromium 内核，安装方式相同：

1. 获取代码（任选其一）：
   - **下载压缩包（推荐）**：前往 <https://github.com/YUMMi0209/mango-player-plus/releases>，下载最新版的 `Mango_Player_Plus_v3.5.zip` 并解压；
   - 或 `git clone https://github.com/YUMMi0209/mango-player-plus.git` 克隆仓库。
2. 打开扩展管理页：
   - Chrome：地址栏输入 `chrome://extensions`
   - Edge：地址栏输入 `edge://extensions`
3. 开启页面右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」（Edge 文案为「加载解压缩的扩展」），选择项目文件夹。
5. 打开芒果TV视频播放页即可使用；建议点击浏览器右上角插件图标，将其固定到工具栏。

> 也可通过 Edge 加载项商店直接安装：[芒着拉片 MG Player+](https://microsoftedge.microsoft.com/addons/detail/%E8%8A%92%E7%9D%80%E6%8B%89%E7%89%87-mg-player/alikcmgpkiphhhnddpelidmilahokmbm)

## 1. 快速上手

1. 在浏览器打开芒果TV视频播放页。
2. 直接用键盘打点：
   - `I` 打入点
   - `O` 打出点
   - `M` 打标记点
   - 用 `J` `K` `L` 变速预览
3. 点击浏览器右上角插件图标，打开日志面板。
4. 勾选需要的记录。
5. 点击「导出日志」得到 Excel 片段表。

## 2. 快捷键速查

| 快捷键 | 功能 |
| --- | --- |
| `J` | 减速播放（逐级减半，最低 0.25X） |
| `K` | 播放 / 暂停（恢复常速） |
| `L` | 加速播放（逐级翻倍，最高 16X） |
| `空格` | 恢复常速（不暂停） |
| `I` | 打入点：记录当前时刻为片段起点 |
| `O` | 打出点：与入点组成一条「片段」记录（自动计算时长） |
| `M` | 打标记点：记录当前时刻，可后续标记颜色 |
| `Shift + I / O / M` | 跳转到最近打下的入点 / 出点 / 标记点 |
| `,` / `.` | 逐帧后退 / 前进（按视频帧率 1 帧） |
| `PageUp` / `PageDown` | 后退 / 前进 1 秒（网页不随之翻页） |
| `S` | 截图：保存当前画面为 PNG（同时复制到剪贴板） |
| `C` | 截图并复制到剪贴板（不下载） |
| `R` | 开始 / 停止录制画面（含声音） |
| `Esc` | 取消进行中的批量截图 / 录制；网页全屏时退出全屏 |

> 在输入框或备注编辑中按键不会触发快捷键。

**标注截图（`Shift + S`）**：进入后自动暂停视频，可在画面上拖框、点击加文字。文字标注字号按截图原始宽度换算（1080p 约 `51px`、720p 约 `34px`，最小 `28px`），输入框里的预览按同一比例显示；开启「嵌入时间码」时右上角还会打上当前时间码（字号不小于文字标注）。`Z` 撤销、`Enter` / 点「保存」导出 PNG、`Esc` 取消。

## 3. 视频控制栏

进入芒果TV视频页后，画面内会出现轻量控制栏。

### 顶部时间码

实时显示当前时间与状态徽章：

- `PLAY`
- `IN`
- `OUT`
- `MARK`
- `REC`

鼠标悬浮画面时，时间码自动平滑下移，避开新版播放器的顶部遮挡；移出画面后回到原位。

点击可复制当前时间码；打点后自动显示入点以来的计时。

全屏状态下：

- 时间码固定下移，位置不随鼠标移动
- 无操作 5 秒后自动隐藏，移动鼠标立即恢复

右键点击可弹出输入框，输入时间码直接跳转。

> 跳转是**帧级校正**的：芒果TV 这类播放器会把 `seek` 吸附到更早的位置（可能早好几帧），所以跳过去之后会核对**实际渲染帧**与目标帧的差并补偿，保证画面与记录的时间码一致。输入框跳转、`Shift + I / O / M`、`#mpp=` 链接、面板点记录跳转、批量截图 / 批量录制都走这条链路。

支持以下格式（**面板里右键双击时间码就地编辑时同样适用**，两者共用同一套解析逻辑）：

- `hh:mm:ss:ff`
- `mm:ss:ff`
- `mm:ss`
- `hhmmssff`
- `mmssff`
- `mmss`

分隔符兼容**中英文冒号与分号**（`:` `：` `;` `；`），**有无分隔符都可以**（如 `01:12:18`、`01：12：18`、`011218` 等价）；帧号必须小于当前帧率、秒必须小于 60，写错会提示「无法识别的时间码」。

操作方式：

- `Enter`：跳转
- `Esc`：关闭

### 鼠标悬停按钮

鼠标悬停画面时，左右两侧浮现圆形按钮：

- 左侧：截图
- 右侧：录制

录制中常驻显示，并带红色描边。

### 弹幕屏蔽

插件在适用站点启用期间自动隐藏视频弹幕，无需手动开启；离开站点或禁用插件后恢复显示。

## 4. 日志面板

点击浏览器右上角插件图标打开面板。

面板顶部「日志记录」下方显示当前视频标题，宽度随窗口自适应，拉宽窗口可显示更多文字。

点击标题即可就地改名：

- `Enter` 保存
- `Esc` 取消

修改后的标题会同步到：

- 「历史记录」列表
- 导出表格的标题列

弹窗 / 侧边栏模式会跟随当前标签页，切换网页后记录自动同步。

## 三种显示模式

点击右上角「模式」按钮可切换：

```text
弹窗 → 侧边栏 → 独立窗口
```

### 弹窗

紧凑窗口，页签切换：

```text
标记 | Mark / 片段 | Clip
```

竖线为主题强调色。

### 侧边栏

浏览器右侧侧边栏，两组记录上下堆叠，可折叠。

### 独立窗口

独立小窗，可脱离浏览器使用。

插件会记忆上次使用的模式：下次打开浏览器，点击右上角插件图标仍按该模式打开面板。

- 弹窗：直接弹出
- 侧边栏 / 独立窗口：会清空弹窗，以对应方式打开

## 记录操作

勾选记录用于导出或删除。

顶部计数标签或底部全选按钮可一键全选（搜索 / 颜色筛选生效时，计数标签上的数字即搜索结果数，点它选中的就是这批搜索结果）。

列表中每条记录左侧的**序号固定两位**（`01`、`02`…），超过两位按实际位数显示（`100`）。

连续多选时高亮合并为一块圆角矩形：

- 仅首尾保留圆角
- 组内分隔线保留淡化

单条选中保持原样。

### 常用操作

- **点击时间码**：跳转到视频对应时刻
- **右键点击时间码**：复制紧凑时间码，例如：

```text
00391214
```

- **右键双击时间码**：就地编辑该时间码（`Enter` 保存 / `Esc` 取消，失焦即保存）；支持与控制栏右键输入相同的格式（含**不带分隔符**的 `hhmmssff` / `mmssff` / `mmss`）；片段记录可分别编辑入点、出点，时长自动重算
- **点击记录行其他区域**：为该条记录添加 / 编辑备注
- **二次确认弹窗**（删除记录、批量截图 / 录制、清除历史等）支持纯键盘操作：`←` / `→` 在「取消 / 确认」之间切换，`Enter` 触发当前按钮，`Esc` 取消；危险操作（删除类）默认焦点停在「取消」，其余默认停在主操作按钮

### 批量截图 / 录制

在面板中勾选记录后（焦点保持在面板内）：

- 勾选**标记点**后按 `S`：弹出确认框，确认后按时间先后**依次自动截图**（批量截图只对标记点生效）
- 勾选**片段**后按 `R`：弹出确认框，确认后按时间先后**依次自动录制**（批量录制只对片段生效，录制入点到出点）
- 确认框里有一个**标题输入框**（默认填当前面板标题）：改成这次批量要用的标题即可，它决定这一批产出文件名的「标题」部分（`标题_时间码_备注`），改完会同步到面板标题
- 勾选类型与按键不符时不执行，提示需要勾选对应类型（标记点 / 片段）
- 任务进行中按 `Esc`：**取消批量任务**（焦点在面板或页面内均可）

执行期间画面会逐条跳转，页面右下角提示当前进度（如 `批量录制 2/5 · Esc 取消`），全部完成后提示成功 / 失败条数；文件名与手动截图 / 录制规则一致。

取消时正在录制的那一段**作废不保存**（避免留下半截文件），已完成的条目保留，提示为「批量录制已取消 — 已完成 N 条」。

批量任务逐条可靠执行：每段录制严格停在设定的出点，单条异常只记为该条失败而不中断整批；换集 / 面板刷新导致控制栏重建后任务仍继续。

### 标记点颜色

点击记录行右侧的色圆点设为对应颜色，再次点击取消。

颜色会写入导出的「颜色」列。

### 备注

带备注的记录始终显示备注行，与所在行的时间码左对齐，无需选中。

多行备注完整展示所有行，编辑与展示状态的换行、行距完全一致。

**点击记录行任意空白区域即可添加 / 编辑该条备注**（无备注时显示「添加备注…」入口；选中单条记录同样会显示入口）。

点击备注即可编辑：

- `Shift + Enter`：换行，输入框随内容自动增高
- `Enter`：保存并退出编辑（**不影响勾选状态**，方便接着批量截图 / 录制）
- `Esc`：取消

底部单行展示：

```text
已选 2条记录 | 3.5s
```

计时器统计已选中的入点到出点记录总时长。

未选中任何入出点记录时不显示。

### 搜索备注

底部「全选」左侧的**放大镜按钮**：点击展开搜索行，输入即按**备注文本**过滤列表（不区分大小写），**命中的关键词会在备注里高亮**；右侧显示「匹配 N 条」/「无匹配」，无结果时列表给出提示。

- **输入框内部靠右**有一排小圆点：点某个颜色只看该颜色的标记点（可多选，**再点一次即取消**，不需要清除按钮）；颜色筛选只对标记点生效
- **搜索生效时，标记 / 片段右侧「全选」上的数字变成搜索结果数**，点它选中的就是这批搜索结果
- `×`：搜索栏为空时**直接关闭搜索栏**；有内容时先清空内容（再点一次关闭）。`Esc` 清除并收起；按钮在有筛选时高亮
- 过滤只影响列表显示，不改变记录与勾选状态 —— 可用来「搜某品牌 → 全选 → 批量截图 / 录制」

## 5. 导出日志

勾选记录后点击「导出日志」，生成 `.xlsx` 表格。

包含两个工作表：

```text
标记 | Mark
片段 | Clip
```

### 标记 | Mark

导出字段：

- 序号
- 时间码
- 颜色
- 备注
- 链接
- 标题

### 片段 | Clip

导出字段：

- 序号
- 入点时间码
- 出点时间码
- 时长
- 备注
- 入点链接
- 标题

链接点击可在浏览器中直接打开并自动跳转到对应时刻。

**单元格格式**：导出的表格（含弹窗里「下载空表」下载的模板）**所有单元格都是文本格式**（`@`），
整列也套了文本格式 —— 时间码这类数字串（`011218`、`00011218`）在 Excel / WPS 里不会变成数字、
不会丢前导零，直接手敲也保持原样。「时长」列按入出点自动算出秒数。

---

## 导出文件命名

**日志（Excel）导出**文件名按以下规则命名：

```text
标题_日志记录_导出时间
```

说明：

- 标题取该条记录的标题（面板上重命名过的标题优先，否则网页标题），清洗非法字符、截断 24 字
- 中段固定为 `日志记录`
- 导出时间为**本机导出时刻**，14 位 `YYYYMMDDHHMMSS`（如 `20260913023512`）
- **不写**记录的时间码与备注（备注只在表格内容里，不参与文件名）；无论选中哪条记录都是同一套规则

示例：

```text
乘风2026_日志记录_20260913023512.xlsx
```

## 6. 历史记录

点击面板右上角历史按钮，列出所有打过分集（视频）的历史记录——**跨网站全局汇总**（在任意网站打过的点都会出现在这里），按记录数排序。

勾选时可连续选择多项，菜单不会关闭。

每行显示：

- 节目标题
  - 与面板上修改过的标题同步
  - 鼠标悬浮时标题变为主题色
- 标记数量
- 片段数量
- 点击该行即可打开对应视频

记录之间以分割线分隔，多选高亮与日志列表一致（合并为圆角矩形）。

记录被删除后，历史列表实时同步移除（含跨网站全局索引）。

顶部提供：

- 「导入」（全选左侧）：打开「导入记录」弹窗，弹窗里**既能从表格文件导入，也能用 AI 导入**
- 「全选」
- 「**导出选中**」（清除选中左侧）：把勾选的视频的日志**批量导出**，未勾选时置灰
- 「清除选中」

### 批量导出日志

勾选多个视频后点「**导出选中**」：

- **只选 1 个视频** → 直接给一个 `.xlsx`，与「导出日志」同一套列、同一套文本格式，文件名同样按 `标题_日志记录_导出时间`
- **选了多个视频** → 每个视频一个 `.xlsx`，**一起打包成一个 zip** 下载（文件名 `日志记录_批量导出N个_导出时间.zip`），解开就是各个视频的日志表
- 记录来源会**自动合并**：该视频在当前站点的本地记录 + 之前导入进来的明细，同一时间码只保留一条
- 导出的表格里**链接带 `#mpp=` 定位**，所以这些文件可以直接再拖回插件导入，记录会按链接回到各自的视频
- 只有记录条数、已经拿不到明细的视频（例如换了设备 / 清过浏览器数据）会被跳过：选中里混有这类视频时会先弹一次确认，导出完的提示里也会写明跳过了几个；全都拿不到明细时只提示、不下载

导入时与当前视频页匹配的记录合并进页面日志（按时间码去重），其他视频的记录进入导入明细并在历史记录中合并显示。

### 导入记录

支持**各类记录表格**（如露出表、植入 / 权益清单等）。入口只有一个：点历史栏的「**导入**」按钮，或把 `.xlsx` 直接拖进插件窗口（支持多文件）。

弹窗是**三步向导**，每步点「下一步」：

**① 选择来源**

- 把 `.xlsx` 拖进虚线区域，或点「点击选择文件」
- 也可以**直接粘贴时间码清单**（手写的、AI 输出的都行）→ 这种情况点「下一步」会跳过第②步，直接进「确认清单」
- 「**下载空表**」（弹窗左下角）：下载本插件的日志记录空表 —— 标记表只有「时间码 / 备注」两栏，片段表「入点时间码 / 出点时间码 / 备注」三栏，各带 30 个空行。只填**时间码**就能用，导入到当前打开的视频

**② 工作表与方式**（从表格导入时才有这一步）

- 选择要导入的工作表：一次只导入一张，列表是**单选**（提示只有一行「共 N 张，选一张」）；多个工作表时默认不选，不选点「下一步」会被拦下；只有一个工作表时直接选中；没识别出时间码的工作表也会带一句说明
- 选择导入方式：**AI 导入（推荐）** 或 **直接导入**

**③ 确认清单**

- 选了 **AI 导入**：给出「**复制提示词**」按钮（提示词只针对你选的那张表）与**AI 结果粘贴框** —— 把表格和提示词一起发给任意 AI，再把结果粘贴进来
- 选了 **直接导入**：直接把这张表的自动识别结果**以时间码清单的形式列出来**
- 无论哪条路，下方都会列出「将导入 N 条」的清单（`时:分:秒:帧` + 说明），**确认无误后点「确认导入」**
- **当前视频已经有记录**时，会先弹一次确认「当前视频已有 N 条记录，确认把 M 条导入到当前视频？」——点了才真正导入

其它说明：

- 提示词约定输出格式：每行「时间码 + 项目说明」；**时间码统一写成规范格式**（`时:分:秒:帧` / `时:分:秒`，原表的中文冒号、分号、纯数字等不规范写法由 AI 转成英文冒号），备注按「**品牌 → 艺人 → 权益 → 时长**」拼接、缺的部分省略（如 `阿维塔 张泉灵 4s`、`趣多多 张彬彬 食用`）
- 粘贴内容兼容纯文本（自动忽略列表符号、序号、markdown 表格外框）与 JSON 数组，也兼容**中文冒号 / 分号 / 不带分隔符**的时间码（`01:12:18`、`01：12：18`、`011218` 都认）
- 时间码自动识别：`HHMMSSFF`、`MMSSFF`、`HHMMSS`、`MMSS`、带分隔符的 `hh:mm:ss:ff`、多打/漏打一位的数字串；**读法自动判定**（6 位按视频时长区分 `MMSSFF` / `HHMMSS`，8 位按 `HHMMSSFF`、4 位按 `MMSS`）
- `011218` 这类 **6 位数字两种读法都成立**时会**弹窗让你确认**一次是「分:秒:帧」还是「时:分:秒」，**默认「分:秒:帧」**：控制栏右键输入时弹窗里只有这两条读法，点哪条就跳到哪条（`↑` `↓` 选择、`Enter` 跳转、点弹窗外面取消）；面板里右键双击时间码、表格导入都会在导入前问一次，整批按你选的同一种读法换算（取消即不导入）
- 导入进来的时间码**一律归一化成标准形式 `HH:MM:SS:FF`** 再进列表 —— 表里手填的 `011218`、`01：12：18`、`00011218` 在面板里都显示成 `00:01:12:18`
- 片段（入点 / 出点）导入时**按入出点自动算出间隔秒数**填进「时长」列，表里没填时长也不影响
- 备注只写**该条对应的项目**：单元格里紧跟时间码的说明与【品牌】标记（`00295306趣多多空镜` → `趣多多空镜`、`【阿维塔】013218` → `阿维塔`），**不带**列分类（植入 / 空镜…）、分线等额外信息；单元格里只有时间码时（露出表这类）退化为品牌 / 秒数（`阿维塔 4s`）
- 同一时刻的重复记录自动合并备注，超出视频时长的行自动丢弃

拖入的文件如果**就是本插件导出的日志**（含从弹窗下载的空表），不弹窗、直接合并；归属规则：

- 行里填了**链接**（本插件导出的链接自带 `#mpp=` 定位）就导入到那条链接对应的视频
- **链接留空 → 导入到当前打开的视频**；下载的空表里没有链接列，所以填好时间码直接导入当前视频
- 时间码用 `011218` 这类 6 位紧凑写法时，导入前会先问一次读法（时:分:秒 / 分:秒:帧），整批套用
- 只有表头、还没填任何记录的空表：提示「空表里还没有记录：填好时间码后再导入」，不会打开导入弹窗

**不是本插件导出的格式**才会打开导入弹窗，并在顶部提示「建议优先用 AI 导入」。记录表 / AI 导入都按**标记点**进到**当前打开的视频**。

「清除选中」可批量清除某个分集的全部记录，有二次确认。

## 8. 常见问题

### 面板提示「当前页面无法访问视频」怎么办？

面板只能在芒果TV视频播放页，或已开启「应用于当前网页」的站点使用。

弹窗 / 侧边栏会自动跟随当前激活的标签页，切换到视频页后即可恢复。

独立窗口会跟随打开时记忆的来源视频标签页。

---

### 按 I / O / M 没有反应？

请先确认焦点不在输入框内。

另外，`J` / `K` / `L` 变速前需先播放视频。

---

### 录制的视频没有声音？

浏览器对录制声音有权限限制。

请确认：

- 视频已播放过，浏览器认为你有权播放
- 浏览器未开启「静音标签页」

部分加密内容可能被浏览器禁止采集声音。

---

### 录制帧率不足 / 画面发顿？

录制编码固定为 **MP4 · H.264 + AAC**，分辨率跟随视频本身，采集链路与 v1.0 一致（实测最顺）：

```text
video.requestVideoFrameCallback  →  源视频每来一个新帧才绘制一次（按 mediaTime 去重）
canvas.captureStream()           →  画布每画一次产一帧，时间戳就是真实绘制时刻
MediaRecorder                    →  H.264 + AAC（请求码率 4K 80 / 1080p 40 / 720p 24 Mbps）
```

- **不做定时重绘**：全尺寸 `drawImage`（1080p 每帧约 8MB 像素搬运）是主线程最大开销，画得越少留给编码器的 CPU 越多
- **不做定帧率重打时间戳**：帧数 ≈ 源帧数、没有重复帧也没有时间戳重排，播放最顺（此前的「定帧率采集 + 节拍器重打时间戳」会因网格与源节奏抖动插重复帧或丢帧，反而发顿）
- **不再中途自动降级**：改帧率要重建时间戳网格，反而引入卡顿；编码吃力时只在诊断日志里标注 `encoderSlow`
- **码率**：`MediaRecorder` 的 `videoBitsPerSecond` 只是目标值，Chromium 的 H.264 编码器实测**只按约 42% 兑现**（1080p 请求 16Mbps → 实得 7.6Mbps；请求 48Mbps → 实得 20Mbps，线性关系、不会饱和）。所以按「想要多少 ÷ 0.42」反推请求值：

  | 分辨率 | 请求码率 | 实测实得 |
  | --- | --- | --- |
  | 4K（≥2160p） | 80 Mbps | ≈34 Mbps |
  | 1080p | 40 Mbps | ≈17 Mbps |
  | 720p | 24 Mbps | ≈10 Mbps |
  | 更小 | 16 Mbps | ≈6.7 Mbps |

  实测脚本：`Material/qc-dev/probe-rec-bitrate.js`（真机录制 + ffprobe 读实际码率）
- 排障时可在视频页控制台看录制诊断：`[MGP-REC] saved {...}` 里的 `fps` / `draws` / `chunkCount` / `videoBits` / `encoderSlow` 能看出实际绘制与编码情况

---

### 换集后记录会丢失吗？

不会。

每条记录都挂在对应分集的 key 下，面板会自动切换显示当前分集的记录。

「历史记录」里可以随时跳回任意分集查看。

---

### 录制出来的视频帧率偏低（如源 25fps 只有 15fps）？

先看控制台 `[MGP-REC] saved {...}`：

| 字段 | 含义 |
| --- | --- |
| `fps` | 源视频校准帧率 |
| `draws` | 实际绘制（= 产出帧）次数；`draws ÷ 录制秒数` ≈ 文件实际帧率 |
| `chunkCount` / `chunkBytes` | 编码产出的数据块数与字节数（越大说明编码越跟得上） |
| `encoderSlow` | `ok` / `lowThroughput` / `stalled`：编码器是否吃紧 |

- `draws ÷ 录制秒数` 明显低于 `fps` → 画面源本身没在产新帧（视频卡住 / 页面后台未渲染）
- `encoderSlow` 非 `ok` → 机器编码能力吃紧：关掉其他吃 CPU 的程序，或降低录制分辨率（本版不提供档位，可用较低清晰度播放后录制）
- 录制现在**一源帧画一次、不做定时重绘**，也不定时重打时间戳，主线程开销最低

---

### 录制出来的视频发灰 / 和原片不一样？

Chromium 的 H.264 编码器有一个「表里不一」的地方：它把**色度按 limited 范围缩放**（×224/255 ≈ 0.878），
却把文件标成 **full-range**。结果就是录出来的**饱和色整体掉饱和度** —— 纯红 `255,0,0` 会解回
`230,0,0`、绿色带上红边，整体看着就是「发灰 / 发闷」。

现在的做法是**只补偿色度**：录制转绘时用 `saturate(113.9%)`（= 1 ÷ 0.878）把饱和度预放大，
抵消编码器的收缩；亮度与黑白灰完全不动，容器标签也保持编码器原生（不改写）。

8 色块图端到端实测（真机录制 → 解码回像素比对，`Material/qc-dev/probe-rec-color.js`）：

| 色块 | 源 | 修正前 | 修正后 |
| --- | --- | --- | --- |
| 纯红 | 255,0,0 | 230,0,0 | **254,0,2** |
| 纯绿 | 0,255,0 | 20,253,8 | **0,253,0** |
| 纯蓝 | 0,0,255 | 0,0,238 | **0,1,254** |
| 黑 / 白 / 中灰 | 0 / 255 / 128 | 准确 | **准确** |
| 最大偏差 | — | 21 级 | **3 级** |

> 此前那套「把画面压到 16-235 + 把容器标签改成 limited」的修正属于反向操作，会让画面更灰
> （纯红只剩 `226,2,4`），已移除。

想核对某个文件的实际色彩信息：

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height,pix_fmt,color_range,color_space,color_transfer -of default=nw=1 "录制文件.mp4"
```

看到 `color_range=pc`（full-range）+ `color_space=bt709` 是正常的（编码器原生标注）；
控制台 `[MGP-REC] remux ok {...}` 里的 `rangeTag` 会是 `unchanged`（表示没有额外的范围改写）。

如果换到别的软件里仍然偏色，把 `ffprobe` 输出与「原片截图 / 录制画面截图」发我，可以直接定位是
画布环节还是编码环节。
